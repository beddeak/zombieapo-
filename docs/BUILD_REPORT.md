# 빌드 및 서버 검증 결과

## 0.2.0 수정 빌드 3 (2026-10-25, 세 번째 피드백 반영)

### 바뀐 점
- **안테나:** 엔드 막대기 모양의 안테나를 추가했다. 라디오 바로 위나 옆(동서남북)에 붙여 설치해야 구조를 요청할 수 있다. 폭발에 부서지지 않고, 웅크려 부수면 회수되며, 피날레와 탈출 중에는 옮길 수 없다. 안테나가 없으면 라디오 이름표가 "안테나를 위나 옆에 설치하세요"로 바뀐다.
- **조립 시간:** 라디오나 안테나를 조합하면 재료 1세트가 들어가고 그 작업대에서 조립이 시작된다(라디오 90초, 안테나 45초). 그동안 좀비 웨이브가 20~25초 간격으로 계속 오고, 작업대 8블록 안에 생존자가 없으면 멈춘다. 끝나면 조합한 사람에게 아이템을 준다. 조립 중인 작업대는 부술 수 없고 폭발에도 남는다. 진행은 저장되어 재시작 뒤 작업대 근처로 오면 이어진다. `stop`하면 아이템을 바로 준다.
- **조합법:** 사용자가 보낸 그림대로 배치가 정해진 조합법으로 바꿨다. 라디오 `DRD/RHR/TBT`(다이아몬드 블록, 레드스톤 블록, 바다의 심장, 레드스톤 횃불, 소리 블록), 안테나 ` C /QRQ/ C `(철 사슬, 네더 석영, 레드스톤 가루). 설정은 `shape`와 `keys`로 바꾸고, 잘못된 모양은 경고 후 기본값을 쓴다.
- **크래프터 차단:** 크래프터(자동 제작기)는 조립을 건너뛰게 되므로 라디오와 안테나를 만들지 못하게 했다.
- **시작 시 몬스터 정리:** 카운트다운이 끝나는 순간 그 월드의 로드된 바닐라 적대적 몹을 지운다. 동물, 주민, 골렘, 이름표 몹, 제외 몹은 남긴다.
- `/apoc radio give`는 라디오와 안테나를 함께 준다(조립 없이 바로). `/apoc status`에 안테나와 조립 진행을 표시한다.
- 조합 이벤트 안에서 바로 창을 닫지 않고 다음 틱에 닫는다(Bukkit에서 클릭 이벤트 중 `closeInventory`는 안전하지 않다).

## 0.2.0 수정 빌드 (2026-10-25, 첫 플레이 피드백 반영)

첫 플레이 로그: `/apoc start` 후 약 1분 만에 커스텀 좀비 307마리, 다시 시작한 뒤 약 1분 30초 만에 301마리를 정리했다(`server/logs/latest.log`).

### 바뀐 점
- 몬스터 대체와 자연 좀비 스폰에 "한 지점 주변 상한"을 적용했다. `count-radius`(48블록) 안의 커스텀 좀비가 `per-player-cap`(기본 25, 날짜·블러드문에 따라 증가) 이상이면 스폰을 막기만 한다. 같은 상한을 쓰는 추가 스폰은 원래대로다.
- 돼지·소·여우 등 동물을 바꾸는 코드는 원래 없었다. 대체 대상은 Bukkit `Enemy`를 구현한 적대적 몹뿐이고, `javap`로 Pig/Cow/Fox가 `Enemy`가 아님을 확인했다. 이를 고정하는 테스트를 추가했다: `Enemy`가 아닌 모든 엔티티 종류 × 모든 스폰 원인 → 무시.
- 게임 안 안내 문구를 모두 존댓말로 바꿨다. 날짜 타이틀은 "N일차"만 띄우고, 부제목과 시작 타이틀은 뺐다.
- 라디오 조합법: 다이아몬드 블록 1 → 2 (재료 합계 9).
- `/apoc egg <타입|all> [수] [플레이어]`: 테스트용 스폰알. 우클릭하면 해당 타입 좀비가 나오고, 바닐라 좀비 스폰·몹에 사용·디스펜서 발사는 막는다.

### 검증
- `build.ps1 -Offline`: `BUILD SUCCESSFUL`, 컴파일 경고 없음. JUnit 9개 클래스 60개 통과.
- 실제 서버 검증은 하지 않았다. 사용자의 서버가 실행 중이고 접속해 있어서 재시작하지 않았다. 스폰알과 주변 상한은 플레이어가 있어야 동작하므로 클라이언트 확인이 필요하다.
- 새 빌드는 아직 `server/plugins`에 설치하지 않았다. 서버를 멈춘 뒤 `setup-server.ps1 -Offline`으로 설치한다.
- 새 빌드 SHA-256: `a400323bba61f7b38a2b6572a045b577ec40019beaebba3af4104783c7bbb595` (설치된 이전 빌드는 아래 표의 `2a20f9c6…`).

### 포트가 25599로 바뀐 원인
- 아래 0.2.0 콘솔 검증 때 기존 서버 폴더에서 `--port 25599` 옵션으로 Paper를 실행했고, Paper가 이 값을 `server/server.properties`의 `server-port`에 저장했다. 그 전에는 25565였다. 사용자가 25565로 접속하지 못한 원인이 이것이다.
- 사용자 결정에 따라 `server/server.properties`를 `server-port=25565`로 되돌렸다(2026-10-25). 서버가 실행 중이라 다음 시작부터 적용된다. 앞으로 검증용 실행은 서버 폴더를 복사한 별도 폴더에서 하고, 원본 폴더에는 포트 옵션을 쓰지 않는다.

### 접속 문제 확인 및 안내 수정 (2026-10-25)

- 현재 `server/server.properties`의 `server-port`는 25599이며 실행 중인 Paper도 `*:25599`에서 대기 중이었다. 실행 스크립트와 문서는 이전 값 25565를 안내하고 있었다.
- 로컬 25565는 연결되지 않았고, 25599 상태 조회는 `Paper 26.2`, 프로토콜 776, 최대 10명, 접속자 1명으로 응답했다.
- 현재 실행 중인 Lunar 클라이언트의 Minecraft 버전은 26.2로 서버와 일치했다.
- 서버 로그에서 로컬 클라이언트 `joined the game`, `logged in`, `/apoc start` 실행과 아포칼립스 시작 성공을 확인했다.
- `start-server.ps1`은 실제 `server-port`를 읽어 표시하도록 수정했다. 서버 설정과 실행 중인 프로세스는 변경하지 않았다.
